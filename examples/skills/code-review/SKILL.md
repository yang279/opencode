# 代码审查

当用户要求 review、审查、检查代码时使用此 skill。

## 步骤

1. 先定位改动范围：读取目标文件，或查看最近的 diff。
2. 从以下维度审查：
   - 正确性：逻辑、边界条件、空值、错误处理
   - 安全：注入、越权、敏感信息泄露、路径遍历
   - 可读性：命名、函数职责、重复代码、注释
3. 输出结论，按「严重 / 一般 / 建议」三级归类，每条附具体位置与修改建议。

## 输出格式

- 🚨 严重：会引发 bug 或安全问题，必须修复
- ⚠️ 一般：影响可维护性或潜在隐患
- 💡 建议：可选的改进

最后给一句总结评价。
